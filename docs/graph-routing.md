# Graph Routing

Graph Routing is Metapi's source-graph and compiled-runtime routing model. A
published source graph is compiled into a flat runtime bundle. The proxy only
loads and executes that bundle; no Route Group side tables exist, and runtime
behavior is never inferred from the editor layout.

## Layers

| Layer | Contract | Responsibility |
|------|----------|----------------|
| Route Group facade | Source Graph `candidate_selector` macros | Structured operational commands and Graph-backed management projection |
| Source graph | `RouteGraphSource` | Semantic routing structure, filters, endpoints, and macros |
| Compiled runtime | `CompiledRouterBundle` | Flattened selection and fallback execution plan |
| Runtime evaluation | Request plus runtime metadata | CEL evaluation, eligibility, selection, retry, and fallback |

Route Groups are a command/read facade over Source Graph, not a persistence
layer or second runtime model. Their IDs are macro IDs, fallback stages and
candidates are macro configuration, and every mutation publishes a new Source
Graph version. Automatic and manual ownership controls editing permissions and
discovery lifecycle only; it does not create a different graph or runtime
shape.

## Core Objects

| Object | Meaning |
|------|---------|
| `entry` | A public downstream request ingress |
| `candidate_selector` macro | A semantic selector with ordered fallback stages |
| `route_endpoint` with `endpointKind: "supply"` | An upstream executable endpoint |
| `filter` | Request transformation before dispatch or upstream build |
| `dispatcher` | A primitive selector, usually generated by macro lowering |
| `synthetic_endpoint` | A configured terminal response such as a 503 fallback |

The graph has no route-table IDs, legacy channels, target pools, or
priority-bucket fields.

## Fallback Stages

`candidate_selector` uses its ordered authoring groups only while lowering.
Lowering emits explicit `dispatcher.fallback.out` links, and the resulting
graph topology defines runtime fallback order:

```text
stage 1: select among primary endpoints
stage 2: select among backup endpoints
stage 3: return a synthetic unavailable response
```

Within a stage, the stage policy chooses an eligible member. The macro policy
is inherited when a stage does not provide its own policy. The next stage is
considered only after the current stage has no eligible execution alternative,
including after retry/failure overlays exclude its alternatives. The compiled
runtime follows those links and does not consult the macro group array.

`priority`, `priority_order`, and candidate-level priority do not belong to
the current source graph or API contract.

## Native Dispatcher Policies

A selector policy is always one of these native references:

```json
{ "kind": "inherit_default" }
```

```json
{ "kind": "registry", "policyId": "platform-default" }
```

```json
{ "kind": "builtin", "builtin": "weighted" }
```

```json
{
  "kind": "inline",
  "policy": {
    "id": "regional-weighted",
    "name": "Regional weighted",
    "kind": "cel",
    "selectionMode": "weighted",
    "contributionExpression": "max(0.0, runtime.routingSignals.normalizedCostScore)"
  }
}
```

The supported built-ins are `weighted`, `round_robin`, and `stable_first`.
CEL policy definitions use `weighted`, `ordered`, `round_robin`, or `direct`
selection modes.

## Compilation And Execution

```text
source graph
  -> validate native contracts
  -> lower macros
  -> compile router bundle
  -> hydrate policy/CEL evaluators
  -> evaluate request and runtime metadata
  -> execute one alternative or continue fallback
```

The compiled runtime retains source references for diagnostics, but execution
does not depend on route-group provenance. Marketplace, Model Tester, proxy
logs, pricing, and routing diagnostics derive their runtime view from the
compiled bundle and its execution traces.

## Publication And Runtime State

Publishing is the single activation boundary. Metapi validates and compiles the
complete Source Graph, stores an immutable runtime artifact with its bundle hash
and source-graph provenance, then atomically moves the active-version pointer.
The proxy resolves the active artifact and never reconstructs routing from Route
Group rows or editor state. A failed validation or publication conflict leaves
the previously active artifact in place.

The artifact is cached by artifact ID and invalidated when a new graph is
published or runtime state is explicitly refreshed. Request-scoped routing
signals (for example cost, balance, usage, health, or compatibility inputs) are
overlaid on the matched compiled plan for evaluation; the stored artifact is
not mutated. Failure overlays and selection constraints further reduce the
eligible alternatives. A forced execution attempt fails closed when it is not
available; a sticky target is honored when available and otherwise excluded so
normal selection can continue.

Filter stages are evaluated in graph order before dispatch. Their operations are
split by phase: `pre_selection` can change the request/model used for selection
and eligibility, while `post_build` operations are collected for application
after an execution target and upstream request have been built. Neither phase
changes fallback ordering.

## Downstream Exposure

Only an `entry` or a `candidate_selector` macro with an `external` surface
creates a downstream model ingress. `route_endpoint` is always a supply
terminal, never a reusable route-product abstraction. Compose graph paths with
edges, embedded macro surfaces, filters, and dispatchers instead of inventing
an internal endpoint type.
